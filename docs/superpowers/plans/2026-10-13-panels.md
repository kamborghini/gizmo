# Panels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On every Reactor page, each section sits in a white panel on a light grey page, so nothing floats.

**Architecture:**
- **Tokens.** New tokens give the grey page, the panel's shadow, its padding and the gap between panels.
- **One stamping pass.** `syncPanels()` runs in the app's existing batched DOM pass (beside `syncToggles`, `syncDialogs` and `syncTableHeads`). It stamps `.panel` on each page's section blocks.
- **Which blocks.** A pure `panelTargets(node)` decides, from each content root's children: it skips headers, tabs and notices, opens holders (pairs, plain wrappers) and returns the blocks.
- **CSS.** One screen-only `.panel` recipe boxes them. Smaller rules make pairs equal height, run tables to the panel's edges and keep the controls readable on the grey.

**Tech Stack:**
- One page, `static/index.html`: HTML, CSS and vanilla JS.
- Tests: `tests/test_frontend.py`, which holds CSS and source assertions plus a node harness, `MINIDOM`.
- The local rig: `.design-rig/wide/all/core.js` with the cluster files (Playwright, never committed).

**Spec:** `docs/superpowers/specs/2026-10-13-panels-design.md`

## Global Constraints

- **Tokens only.** No literal colours or sizes in rules. A new colour is a tier 1 primitive read through a tier 2 token, and the token guard tests must pass (`t_every_defined_token_is_read`, `t_screen_css_carries_no_arbitrary_lengths`).
- **Screen only.** Every panel rule sits under `@media screen`, so a report printed to PDF keeps its plain white page. `t_the_printed_sheets_do_not_change` must pass unchanged.
- **Frozen.** The printed label, the A4 and courier sheets, the print document, `LABEL_LOGO` and the print CSS; the Production Manager queue's content, columns, statuses, actions and their order; the Quote Engine.
- **On-screen rules.** One teal (`.btn-primary`) per screen at most. No illustrations. British English, and no em or en dashes in on-screen words or release notes.
- **Release note.** Every app change needs a `data/changelog.json` release dated on or after the merge day. Release notes never say API, webhook, callback URL or JSON.
- **The repo is public.**
  - Never commit `audit/`, `.superpowers/` or `.design-rig/`.
  - Never write the business name in docs, plans or commit messages.
  - Ship only through a pull request, after Cameron's explicit yes on before-and-after shots.
- **`make check`** passes before every push. Run it as `env -u ANTHROPIC_BASE_URL -u CLAUDE_CODE_MESSAGING_TOKEN make check`.
- **Agent budget for this task is 5.** At most 2 are used, for the reviews in Task 9.
- **Rulings made while planning.** Each gives its cost if wrong.
  - **Chat.** The Chat view keeps the white sheet as its ground: its conversation is a reading column, not sections (spec section 7). Only the start screen's recent list is a panel. Cost if wrong: Chat alone has no grey page.
  - **Token names.** The spec names `--panel-pad` and `--panel-pad-phone`. The plan uses `--panel-pad-y` and `--panel-pad-x`, with a phone `:root` override of the same names, so every rule reads one name. The values are the spec's: 20 by 24, and 16 on a phone. Cost if wrong: a rename.
  - **Paper.** On screen the gap between sections is 20 (12 on a phone). Paper keeps today's 48, because spec section 1 keeps a printed report on its current rules. Cost if wrong: a printed report is airier than the screen.
  - **Tables.** Only tables bleed to a panel's edges, and only above 640; the reasons are in Task 4. Cost if wrong: a list's rules, and a phone table's rules, stop at the panel's inset.
  - **Saved layouts.** No widget's id changes. The DOM probe found every report page's headings already inside their widgets; the one loose heading, on a product's page, is not on a Customise page. So the spec's "an old saved layout naming a merged heading still loads" test has nothing to pin. If Task 5's probe finds a loose heading on a Customise page, its fix keeps the content's widget id and adds that test (`wgMergeOrder` drops ids it does not know). Cost if wrong: one test.

## Review Focus

1. **Customise mode on a page of panels.**
   - Expected: the dashed edge sits on the panel's own edge, and the hide button and grip stay inside the panel's corner.
   - Pairs, which are not panels themselves, keep their dashed edge 8 outside.
   - Pinned in Task 2 by a CSS test and checked in the Customise shots in Task 6.
2. **Printing a report to PDF.**
   - Expected: no grey page, no panel edges or shadows, the plain sheet as today.
   - Pinned in Task 2: every `.panel` and canvas rule sits inside `@media screen`.
3. **A table in a panel at a middle width (900 to 1280).**
   - Expected: its two-line rows keep the panel's inset and nothing scrolls sideways.
   - Pinned in Task 4: the row padding is not inside a container query, so it applies in both modes. Measured at 1280 in Task 6.
4. **A page state the probe did not see.** A run gate, a failed load (`loadFailure`), a loading line or an empty state.
   - Expected: a run gate, an empty state and a loading line are panels; an error message and a notice are not.
   - Pinned in Task 2 by the node test of `panelTargets`.
5. **A figure group as a panel.**
   - Expected: its first figure has no hairline before it, and its figures are not clipped.
   - Pinned in Task 2: the group's inset is a transparent border, not padding, so `overflow: clip` still clips at the group's own edge. Measured in Task 6.

        /* PANELS (13 Oct 2026, docs/superpowers/specs/2026-10-13-panels-design.md):
           every section of a page sits in a white panel on the grey page. A page's
           content root (.ov-wrap) holds its sections; panelTargets says which of
           its children, or of what they hold, is a panel, and the batched pass
           stamps .panel on them, so a page added next year is boxed without
           anyone wiring it. The header, tabs, choosers, notices, the queue's
           counters and Forecast's own tinted band stay on the page. */
        const PANEL_SKIP = ['ov-hero', 'page-tabs', 'tabs', 'seg-row', 'queues', 'segmented', 'back-btn', 'miss-strip', 'msg', 'alert', 'fband', 'guide-tools', 'sr-only'];
        const PANEL_HOLD = ['wpair', 'wpair-in', 'fc-pair', 'fc-cols', 'crm-seg', 'crm-charts', 'guide-host', 'guide-grid', 'ds-page'];
        function panelTargets(n) {
            if (!n || !n.classList || n.tagName === 'INPUT' || n.tagName === 'SCRIPT') return [];
            if (PANEL_SKIP.some(c => n.classList.contains(c))) return [];
            if (!n.className || PANEL_HOLD.some(c => n.classList.contains(c))) return [...n.children].flatMap(panelTargets);
            return [n];
        }
        function syncPanels() {
            document.querySelectorAll('.ov-wrap').forEach(root => [...root.children].flatMap(panelTargets)
                .forEach(t => { if (!t.classList.contains('panel')) t.classList.add('panel'); }));
        }
