# Stack currency audit, 2 October 2026

Cameron: "audit the entire architecture of this app and make sure everything is running the latest version of tools etc."

Every versioned part of Reactor was checked against its latest stable release on 2026-10-02. That covers the Python libraries and runtime, the forecast image, Shopify (Admin API, webhooks, extensions, auth), every outside service, CI, the base images and the update process. Four research agents did the work. They read official changelogs and migration guides, and tried the upgrades for real in scratch environments: the full test suites on the latest libraries, on Python 3.14, and against the newer Shopify extension packages. Nothing in the repo, the store or production was changed. Claims about the hosting platform's settings are marked "not checkable".

Re-checked by hand before writing this: PY-01 (a clean resolve of requirements.txt does not include requests), BR-01 (Dependabot alerts and security fixes are off and it has never opened a pull request), and BR-02 (today's CI run carries GitHub's warning that its actions are forced from Node 20 to Node 24, and that ubuntu-latest moves to Ubuntu 26 from 2026-10-19).

## Headlines

- **Nothing critical.** pip-audit finds no advisories at the current pins or at the latest versions, on Python 3.12 or 3.14.
- **A latent break (PY-01).** Google's service-account sign-in cannot work on a fresh deploy: `requests` was removed on 2026-09-07 because nothing imported it, but google-auth's transport does, lazily. The local environment hides it. Whether production uses the service account or the OAuth connection is not checkable.
- **Unsupported or stale libraries.** mcp 1.28.1, which serves the whole app, is outside mcp's supported set; 1.30.0 is the newest supported 1.x. anthropic 0.104.1 is on a line that stopped at 0.125.0. pypdfium2 4.30.0 bundles a PDFium from May 2024 and opens PDFs from strangers' emails.
- **The automatic updates were never on (BR-01).** .github/dependabot.yml has existed since 2026-09-03, but Dependabot is off in the repo's settings, so nothing has been proposed.
- **CI runs on borrowed time (BR-02, BR-10).** The pinned actions are v4/v5 built for Node 20, which GitHub removed on 2026-09-23. ubuntu-latest moves to Ubuntu 26 between 2026-10-19 and 2026-11-19.
- **The images are older than CI sees (BR-03).** The images' own pip (25.0.1) has six advisories that CI never scans.
- **Python 3.12 is security-only.** 3.14 works: every library has 3.14 wheels, and the suites pass once one test helper stops calling `asyncio.get_event_loop()`.
- **The forecast image floats (BR-05).** Its `>=` pins mean a rebuild today would take whatever is newest, including pandas 3.
- **Shopify is supported but behind.** The Admin API default is 2026-07; the webhooks and both print extensions are on 2026-04; 2026-10 is stable. One real behaviour change is waiting in 2026-10: an address edit recalculates tax (SHOP-02).

## Proposed plan

**Batch 1, low risk (Claude):**
- Restore `google-auth[requests]`, with an import test.
- Pin mcp 1.30.0, anthropic 1.11.0, pypdfium2 5.13.0 (call `get_text_bounded`), starlette 1.7.0, uvicorn 0.54.0, google-auth 2.59.1, boto3, cryptography 50.0.2, pydantic 2.13.5, beautifulsoup4 4.15.0 and python-barcode 0.16.1. These were trialled together: 907 passed and 1 failed, the failure being the known load-sensitive timing test.
- Move the GitHub Actions to v7 by SHA.
- Upgrade pip to 26.2.1 in both images.
- Move Search Console to its current host.
- Bring the price table up to date, fix the API-version guard test, and harden the timing test.

**Batch 2, structure (Claude):**
- Move the app, the forecast image and CI to Python 3.14, after the test-harness fix.
- Add hashed lock files for the app and the forecast image, with exact pins.
- Pin the base images by codename and digest.
- Rewrite dependabot.yml to cover /forecast, with grouping and a cooldown.
- Add CI jobs that scan the images and build the extensions.
- Pin Node in CI.

**Batch 3, Shopify (Claude, then Cameron's deploy):**
- Show tax and total changes after an address edit (SHOP-02), then raise the Admin API to 2026-10.
- Move the webhooks to 2026-10.
- Move the print extensions to 2026-07 with a version range, and to 2026-10 once Shopify publishes the package.
- Cameron then runs `shopify app deploy --no-release`, checks it, and releases.

**Later, larger:**
- Port to mcp 2.x. It needs a host allowlist and a new test; without them every real /mcp call returns 421.
- Move the deprecated REST product and variant reads to GraphQL. There is no deadline for this app.
- Move the Pipedrive field reads to v2.

**Cameron only:**
- Switch on the Dependency graph, Dependabot alerts, security updates and version updates (GitHub, Settings, Advanced Security).
- Add a ruleset on main requiring the "test" and "forecast" checks.
- Confirm whether the Google connection in production is the service account or OAuth.
- Confirm the hosting platform waits for GitHub checks before deploying.
- Check the Xero app's tier and connection count.
- Run the Shopify deploy after Batch 3.
